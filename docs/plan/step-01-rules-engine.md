# Step 01：规则引擎核心

## 目标

实现 `core/` 下的纯逻辑基础模块与测试，不依赖场景树，可无界面运行。

## 前置

无。必读文档：code-style.md、architecture.md、game-rules.md **全部**（§3、§7、§8 是重点）。

## 任务

1. `core/card.gd`：牌的表示（花色、点数、副本序号、分值、是否王）。
2. `core/deck.gd`：162 张牌构建、洗牌、发牌（39×4 + 底牌 6）。
3. `core/play.gd`：牌型识别（单张/棒子/滚子，其余非法）；两手牌的大小比较（规则 §7.3：同花色同牌型比大小；主杀副须同牌型；垫牌判小）。
4. `core/trick.gd`：一轮出牌的跟牌合法性（规则 §7.2：张数相同、有同花色必须跟、不足可垫但判小）与赢家判定、分牌收取。
5. `core/bidding.gd`：叫价表示（级牌×1/×2/×3、小王×3、大王×3、首局大王）、优先级比较（规则 §4.4）、给定手牌的合法叫价枚举、主花色确定。
6. `core/tribute.gd`：进贡数量与方向计算（规则 §5，含向上取整与底牌王加成）、贡牌合法性（手中最大非分牌）、还贡合法性（非分副牌）。
7. `core/bottom.gd`：扣底/扣王合法性（有大王先扣大王）、干锅判定（规则 §6）。
8. `core/settlement.gd`：结算矩阵（规则 §8 全部 7 分支 + §9 特殊结束 + 干锅时王奖励作废）、升级应用（落点不跳过 3/10、10 级再升级 = 赢整场）。
9. `tests/`：test_runner.gd + 上述每类的测试。

## 产出文件

`core/card.gd`、`core/deck.gd`、`core/play.gd`、`core/trick.gd`、`core/bidding.gd`、`core/tribute.gd`、`core/bottom.gd`、`core/settlement.gd`、`tests/test_runner.gd`、`tests/test_*.gd`

## 验收标准

- 规则 §8 的 7 个结算分支、§9 的 3 个特殊结束各有至少一个测试用例。
- 规则 §7.3 的已确认例子各有用例：主牌单张杀不了副牌棒子；主牌棒子能杀副牌棒子；垫牌判小；单张轮主牌单张可杀副牌单张。
- 进贡计算用例：75 分 → 2 张；115 分 → 1 张；160 分 → 2 张；130 分 → 方向反转。
- `godot --headless --path . -s res://tests/test_runner.gd` 全部通过；无 CLI 则注明未运行。
